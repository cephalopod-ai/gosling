# gosling v1.2.5

## Status

`v1.2.5` is the current source candidate. It has not been tagged, packaged, or published. The
latest published GitHub release is named `v1.2.4` and is attached to the historical
`release_v1.2.4` tag; the annotated `v1.2.4` tag identifies the same source commit.

This candidate contains eight commits after `v1.2.4`, with 11,004 insertions and 18,750 deletions
across 234 files. Most deletions are the deliberate removal of the unused duplicate REST server,
Desktop OpenAPI schema, and obsolete provider implementations—not lost session functionality.

## Highlights

- **Full Session Handoff continuity.** Provider and model changes can use inspectable, bounded,
  redacted checkpoints instead of replaying the entire raw transcript. Transitions retain the
  previous provider until target initialization, acknowledgement, and the atomic database commit
  succeed.
- **Selectable crash recovery, Safe by default.** Desktop offers **Manual**, **Safe
  (recommended)**, and **Always** policies for a task interrupted by an unexpected stop. Safe
  resumes only when the backend confirms an interrupted turn and all recovered tool calls have
  saved successful results.
- **Multiline prompt composition.** `Enter` inserts a newline. Use `Cmd+Enter` on macOS,
  `Ctrl+Enter` on Windows/Linux, or the **Send** button to submit. While a task is running, the
  keyboard shortcut follows queue behavior; clicking **Send** interrupts immediately.
- **Outputs open as outputs.** Valid local files embedded in tool results open directly, workspace
  output roots participate in artifact resolution, and unambiguous stale bare-name aliases are
  rebound to their qualified output. The workbench also gains **Close all**, while blocked files
  cannot be bulk-selected.
- **One supported interface boundary.** The unused `gosling-server` REST crate and its Desktop
  OpenAPI surface were removed. Desktop and external integrations now use the core ACP server and
  generated ACP types rather than maintaining duplicate REST behavior.

## Session continuity and recovery

The handoff checkpoint is built deterministically from the persisted session ledger without asking
the outgoing provider to summarize itself. It can preserve verified work, decisions, touched
files, checks, unresolved questions, recent context, and operation state. Common credential,
authorization, private-key, and secret-query shapes are redacted before persistence and delivery.
Raw reasoning, tool arguments, images, and binary payloads are excluded from the recent transcript
tail.

Checkpoint size is capped at the smaller of 16,000 estimated tokens or 10% of the target context
window. After activation, covered messages stay visible to the user but become model-invisible; one
hidden checkpoint becomes the new context boundary. Provider capabilities classify native resume,
history import, summarized bootstrap, and new-context-only transitions without provider-name
branching. Built-in adapters currently use summarized handoff or new context; none currently claims
verified native resume/import.

Crash recovery is separate from handoff. Recovery starts a new model turn from saved history; it
cannot restore the exact interrupted provider stream. **Always** may repeat an external side effect
when a tool result is missing or failed. Permission prompts still apply in every mode, and a normal
Desktop shutdown clears pending recovery instead of restarting the task.

See [Session Handoff](../guides/sessions/session-handoff.md) for the checkpoint, transition, review,
retention, and recovery contracts.

## Desktop workflow

- Prompt composition, editing, voice dictation, and queueing display the platform-specific send
  shortcut consistently.
- Tool-result embedded resources with a valid local URI path open through the guarded file route;
  non-file content continues to use the existing content preview.
- Assistant artifact discovery now checks the working directory first, then pinned workspace output
  and granted roots. It deduplicates only exact or unambiguous aliases, so same-named files in
  multiple qualified locations remain distinct.
- Persisted preview tabs pointing at a dead bare alias are rebound to the qualified output. Missing
  history remains represented, and inventory metadata alone still grants no filesystem access.
- **Close all** clears the session's artifact tabs and active tab together. Files blocked by preview
  policy remain visible but cannot be newly selected for batch operations.

## Architecture and maintenance

- Removed the unshipped `gosling-server` REST crate, old route implementations, server-specific
  OpenAPI generator, and `ui/desktop/openapi.json`.
- Desktop continues to launch `gosling serve`, which exposes ACP over HTTP/WebSocket. Embedders can
  use `gosling acp` over stdio or `gosling serve`; the removed REST endpoints are not a compatibility
  surface.
- Consolidated duplicate interactive CLI session selection behind
  `resolve_or_prompt_session_id` and removed the obsolete task-execution display path.
- Removed unregistered Amp ACP, Avian, and Gemini OAuth modules plus the legacy one-shot `codex`
  provider. Supported alternatives include `codex-acp` and `chatgpt_codex`.
- Default CLI builds no longer enable the optional `code-mode` feature. Custom builds that require
  it must enable that feature explicitly.
- Release builds now strip symbols, use thin LTO, and use one code-generation unit. Debug and test
  profiles are unchanged.
- The release-version recipe no longer requires or stages the deleted Desktop OpenAPI file.
- Shell scope inspection now follows unambiguous `cd` targets across command segments, reducing
  false out-of-scope prompts without allowing navigation outside configured roots.

## Compatibility and breaking changes

- The removed REST routes and `ui/desktop/openapi.json` are no longer available. Integrations must
  use ACP rather than the retired `gosling-server` API.
- Configurations selecting the removed direct `codex` provider must move to `codex-acp` for the
  Codex CLI ACP adapter or `chatgpt_codex` for gosling's ChatGPT OAuth provider.
- Source builds that relied on `gosling-cli` enabling `code-mode` by default must request the
  feature explicitly.
- Session schema v33 adds handoff storage. Existing sessions are migrated in place; ordinary
  session export excludes internal handoff snapshots.

A complete compatibility run across every provider, extension, operating system, and custom source
consumer has not been performed.

## Known issues

- Provider-managed sessions can still receive a gosling-generated `<compaction>` countdown from the
  per-turn context injector. That value is derived from last-request usage, including cache reads,
  and can become negative or fluctuate even though the connected CLI owns compaction. This can
  prompt a model to recommend an unnecessary fresh session. Clamping the number is not sufficient;
  the field must be suppressed when context ownership is not gosling's.
- The Electron development fixture has an intermittent Vite reload/dynamic-import startup race.
- Installed Desktop, signing, artifact, updater, and clean-machine release gates remain open.
