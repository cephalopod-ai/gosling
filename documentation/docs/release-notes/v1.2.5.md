# gosling v1.2.5

## Status

`v1.2.5` is the current source candidate. A `v1.2.5` tag was pushed on 2026-09-10 at `4c3dbdf32`,
and a GitHub release page of that name exists, but it has no attached binaries: the tag-triggered
Release workflow failed at the macOS certificate-import and Windows signing-login steps. The
2026-09-13 audit-repair series, host-enforced planning, Context History, and the Recall Brief all
landed after that tag, so the tag does not contain them. A local arm64 package was built and installed on 2026-09-13 as validation evidence only.
No distributable `v1.2.5` package has been published.

The candidate now includes the 2026-09-13 consolidated audit-repair series, the 2026-09-13
host-enforced planning slice, the 2026-09-14 Context History ledger, and the 2026-09-14/15 Recall
Brief action in addition to the original continuity, Desktop, compaction, and architecture work.
Earlier large deletions are the deliberate removal of the unused duplicate REST server, Desktop
OpenAPI schema, and obsolete provider implementations—not lost session functionality.

## Highlights

- **Durable host-enforced planning (staged source candidate).** The current source adds persisted
  plan generations and revisions, bounded read-only planning capabilities, exact feedback and
  approval, CLI lifecycle commands, typed ACP, and a first-party Desktop review surface. Approval
  does not execute work or change authorization mode or history; implementation is a separate
  action. While a generation is open, gosling also denies app-direct actions, command-backed hooks,
  implicit hint-file reads, side-channel report actions, and provider or model transitions, and
  native session export carries plan history as an explicit, identity-remapped `plan_history_v1`
  section whose transferred generations are stored as stale. Automated broad conformance is
  complete; final packaged and cross-platform Desktop operator acceptance remains open, so this is
  not a shipped-availability claim.
- **Full Session Handoff continuity.** Provider and model changes can use inspectable, bounded,
  redacted checkpoints instead of replaying the entire raw transcript. Transitions retain the
  previous provider until target initialization, acknowledgement, and the atomic database commit
  succeed.
- **Selectable crash recovery, Safe by default.** Desktop offers **Manual**, **Safe
  (recommended)**, and **Always** policies for a task interrupted by an unexpected stop. Safe
  resumes only when the backend confirms an interrupted turn and all recovered tool calls have
  saved successful results.
- **Multiline prompt composition.** `Enter` inserts a newline. Use `Cmd+Enter` on macOS,
  `Ctrl+Enter` on Windows/Linux, or the **Send** button to submit. While a task is running, the
  keyboard shortcut follows queue behavior; clicking **Send** interrupts immediately.
- **Outputs open as outputs.** Valid local files embedded in tool results open directly, workspace
  output roots participate in artifact resolution, and unambiguous stale bare-name aliases are
  rebound to their qualified output. The workbench also gains **Close all**, while blocked files
  cannot be bulk-selected.
- **One supported interface boundary.** The unused `gosling-server` REST crate and its Desktop
  OpenAPI surface were removed. Desktop and external integrations now use the core ACP server and
  generated ACP types rather than maintaining duplicate REST behavior.
- **Honest, bounded automatic compaction.** A configured proportional reduction now remains
  authoritative for short sessions and can stop between completed tool pairs inside one large
  turn. Triggering, budgeting, persisted post-compaction usage, and Desktop all share one active
  context quantity and the active provider route's effective limit; the UI marks that estimate as
  `est` and keeps last-request usage distinct. A 25% reduction at an 80% threshold targets 60%.
- **Context History for compaction (source candidate).** Each successful manual or automatic
  compaction now appends one independent, versioned record holding the exact summary, the stable
  message IDs it covered, the trigger, the provider with its requested and resolved model, usage and
  token estimates, and integrity hashes. Read, compare, pin, export, delete, and prune it from
  Desktop **View Context History** or `gosling session context-history`, and set retention, grace,
  per-session count, and storage limits under **Settings → App → Context History** or
  `GOSLING_COMPACTION_HISTORY_POLICY`. Normal session exports and sharing still exclude these
  records, and explicit export requires an acknowledgement.
- **Opt-in Recall Brief reporting (ACP only).** A read-only `_gosling/unstable/session/recall/brief`
  action interprets results from a selected enrolled Muninn extension, pins every source to its
  exact store, memory, and revision, separates reported beliefs from world claims, checks quotes
  against the returned windows, and degrades to an evidence-only or partial report instead of
  asserting unvalidated conclusions. This is an ACP integration surface in source; there is no CLI
  or Desktop workflow for it yet.
- **Visible CLI failures and stable provider switching.** Claude Code terminal error results now
  reach the chat as provider failures instead of producing a successful empty turn. Handoff source
  hashes canonicalize map-backed session state, so an unchanged preview cannot be rejected merely
  because extension fields serialized in a different order.
- **Reference-aware checkpoints.** A latest request that names “the playtest,” “that scenario,” or
  another earlier label now carries bounded, redacted matching excerpts into the checkpoint. The
  receiving model resolves those references before planning and uses Session History only when the
  retained evidence remains ambiguous.
- **Audit-driven reliability and privacy repairs.** `doctor` verifies the configured provider,
  interrupted turns retain honest durable history, and `--no-session` keeps prompts and responses
  out of durable session and request logs. Subagent activity is deduplicated by durable request
  identity, and Desktop preserves structured missing-folder recovery detail.
- **Bounded data-path corrections.** File-backed memory reads the newest line-aligned bounded
  window, research output checks stay fail-closed, current token counters reset with truncation,
  session database initialization is serialized across processes, and import/handoff work is
  reduced without weakening metadata validation.

## Session continuity and recovery

The handoff checkpoint is built deterministically from the persisted session ledger without asking
the outgoing provider to summarize itself. It can preserve verified work, decisions, touched
files, checks, unresolved questions, recent context, and operation state. Common credential,
authorization, private-key, and secret-query shapes are redacted before persistence and delivery.
Raw reasoning, tool arguments, images, and binary payloads are excluded from the recent transcript
tail.

Distinctive terms and quoted labels in the latest request select six relevance-centered
`referencedContext` excerpts at the baseline budget and up to 24 at the largest budget, with the
immediately preceding assistant response as the fallback for pronoun-only requests. This bounded
selection can recover user-visible evidence behind an older agent-context boundary without
replaying the old raw transcript. Under pressure, generic evidence is trimmed oldest first and
reference matches are trimmed least-relevant first.

Checkpoint size is capped at the smaller of 64,000 estimated tokens or 10% of the target context
window. Structured evidence scales from 4,000 to 16,000 tokens and the inspected tail from 80 to
320 messages as that budget grows. After activation, covered messages stay visible to the user but
become model-invisible; one hidden checkpoint becomes the new context boundary. Provider
capabilities classify native resume, history import, summarized bootstrap, and new-context-only
transitions without provider-name branching. Built-in adapters currently use summarized handoff or
new context; none currently claims verified native resume/import.

Crash recovery is separate from handoff. Recovery starts a new model turn from saved history; it
cannot restore the exact interrupted provider stream. **Always** may repeat an external side effect
when a tool result is missing or failed. Permission prompts still apply in every mode, and a normal
Desktop shutdown clears pending recovery instead of restarting the task.

See [Session Handoff](../guides/sessions/session-handoff.md) for the checkpoint, transition, review,
retention, and recovery contracts.

## Context History

`sessions.db` gains an append-only ledger for context compaction. Every successful compaction stores
one complete, independent snapshot rather than a delta chain, so any record can be read, pinned, or
deleted without its neighbours. Durable compaction commits the conversation rewrite, the usage
update, and the ledger append in one transaction; a compacted-tail Desktop resume records a
temporary record without replacing unloaded history; and cancelled or failed provider work records
nothing.

The Desktop dialog shows token reduction and provenance for each snapshot, an optional changes-only
comparison with the previous available snapshot at word or line granularity, and an on-demand source
viewer that reports rows which no longer exist or were captured without a stable ID. The CLI covers
the same ledger with `gosling session context-history list|show|export|pin|unpin|delete|prune`
(alias `compactions`).

Default policy keeps snapshots for 90 days, waits another 7 before cleanup, targets 100 snapshots per
session, and caps all payloads at 256 MiB; pinned snapshots are exempt from both expiry and cleanup.
Setting the policy in the process environment makes the Desktop controls read-only. Because the
policy lives in the configuration file and the ledger lives in SQLite, gosling finishes
reconciliation, cleanup, and statistics inside the pending database transaction before saving the
configuration, and reports an unresolved post-save failure as a partial apply.

Context History is local walkthrough and recovery history. It is not tamper-proof, not a
compliance-grade audit log, and deletion removes logical rows without guaranteeing erasure from
SQLite pages, WAL files, backups, or filesystem snapshots. See
[Smart Context Management](../guides/sessions/smart-context-management.md#context-history) and
[Configuration Files](../guides/config-files.md#context-history-policy).

## Desktop workflow

- Prompt composition, editing, voice dictation, and queueing display the platform-specific send
  shortcut consistently.
- Tool-result embedded resources with a valid local URI path open through the guarded file route;
  non-file content continues to use the existing content preview.
- Assistant artifact discovery now checks the working directory first, then pinned workspace output
  and granted roots. It deduplicates only exact or unambiguous aliases, so same-named files in
  multiple qualified locations remain distinct.
- Persisted preview tabs pointing at a dead bare alias are rebound to the qualified output. Missing
  history remains represented, and inventory metadata alone still grants no filesystem access.
- **Close all** clears the session's artifact tabs and active tab together. Files blocked by preview
  policy remain visible but cannot be newly selected for batch operations.

## Architecture and maintenance

- Removed the unshipped `gosling-server` REST crate, old route implementations, server-specific
  OpenAPI generator, and `ui/desktop/openapi.json`.
- Desktop continues to launch `gosling serve`, which exposes ACP over HTTP/WebSocket. Embedders can
  use `gosling acp` over stdio or `gosling serve`; the removed REST endpoints are not a compatibility
  surface.
- Consolidated duplicate interactive CLI session selection behind
  `resolve_or_prompt_session_id` and removed the obsolete task-execution display path.
- Removed unregistered Amp ACP, Avian, and Gemini OAuth modules plus the legacy one-shot `codex`
  provider. Supported alternatives include `codex-acp` and `chatgpt_codex`.
- Default CLI builds no longer enable the optional `code-mode` feature. Custom builds that require
  it must enable that feature explicitly.
- Release builds now strip symbols, use thin LTO, and use one code-generation unit. Debug and test
  profiles are unchanged.
- The release-version recipe no longer requires or stages the deleted Desktop OpenAPI file.
- Shell scope inspection now follows unambiguous `cd` targets across command segments, reducing
  false out-of-scope prompts without allowing navigation outside configured roots.
- The per-turn context injector no longer emits gosling's `<compaction>` token countdown into
  sessions whose provider manages its own conversation context. That countdown was derived from
  last-request usage, including cache reads, and could turn negative or oscillate for
  provider-managed sessions and prompt unnecessary fresh-session advice; the rest of the turn
  context is unchanged, and gosling-managed sessions keep the countdown.

## Compatibility and breaking changes

- The removed REST routes and `ui/desktop/openapi.json` are no longer available. Integrations must
  use ACP rather than the retired `gosling-server` API.
- Configurations selecting the removed direct `codex` provider must move to `codex-acp` for the
  Codex CLI ACP adapter or `chatgpt_codex` for gosling's ChatGPT OAuth provider.
- Source builds that relied on `gosling-cli` enabling `code-mode` by default must request the
  feature explicitly.
- Session schema v33 adds handoff storage, v35 adds plan storage, and v36 adds the Context History
  ledger. Existing sessions are migrated in place; ordinary session export excludes internal handoff
  snapshots and Context History payloads, and existing sessions are not backfilled with compaction
  records that cannot be reconstructed.
- `GOSLING_COMPACTION_HISTORY_POLICY` is a new versioned configuration object. Leaving it unset keeps
  the documented defaults; setting it in the process environment makes the Desktop controls
  read-only.

A complete compatibility run across every provider, extension, operating system, and custom source
consumer has not been performed.

## Known issues

- The Electron development fixture has an intermittent Vite reload/dynamic-import startup race.
- Installed Desktop, signing, artifact, updater, and clean-machine release gates remain open.
