# gosling v1.4.0

## Status

As of September 29, 2026, the Rust workspace and Desktop package declare `1.4.0`. A local macOS
arm64 package built from `b69804da55019d787e6797e297cf2d7007f71e57` was installed and launched
successfully, with its embedded backend and rendered chat interface visible. This was an ad-hoc
signed local build. These notes do not establish a published release, Developer ID signing,
notarization, or updater availability.

## Desktop changes

- **Backend connection guidance.** Startup failures distinguish rejected authentication, TLS,
  unexpected HTTP responses, and an unreachable server. A closed connection now shows
  **Connection interrupted** and **Reconnect**, including while the chat is idle.
- **State follows its backend.** Preview tabs, workspace chat filters, composer history, archives,
  and crash-recovery markers identify the backend they belong to. Changing an external backend
  does not reuse another server's state just because session IDs match. Legacy state with unknown
  ownership is preserved without being assigned to the new backend.
- **Folder access.** Ordinary launch does not grant the Outputs pane access to the entire home
  folder or a parent of it. Explicit native folder selection remains available; broad grants are
  limited to the selecting window. An unauthorized optional Git branch lookup simply leaves the
  branch unavailable.
- **Previews and composition.** Rapid tab switches keep image content paired with its selected
  file, including SVG files with Unicode text. Hidden chat composers no longer share input IDs or
  take focus from the active composer; saved drafts and queues remain intact.
- **Completion notices.** Background notifications describe a finished response rather than
  promise the task succeeded. Failed, cancelled, refused, or limit-stopped turns do not generate
  that completion notice. Notification preferences and plan-review handling remain in force.
- **Credential storage wording.** Provider/profile notices identify the backend's configured
  storage. The OS keyring is the default; when disabled or unavailable, the fallback is an
  owner-protected plaintext file, not encrypted storage.
- **Isolated Research Library.** With `GOSLING_PATH_ROOT`, the default Research Library is created
  inside that root. A library explicitly selected in settings still takes precedence.

See [Workspaces](/docs/guides/workspaces), [session actions](/docs/guides/sessions/in-session-actions),
[backend troubleshooting](/docs/troubleshooting/known-issues#desktop-backend-connection), and
[test environment isolation](/docs/guides/environment-variables#development--testing).

## Validation and remaining work

The September 29 Desktop repair run passed **211 test files / 1,628 tests**, typecheck, ESLint,
i18n checks/compilation, and focused browser replays for reconnect, backend state isolation, and
image/SVG switching. The later local package passed release-backend and GUI builds, signature and
hash checks, and normal installed-app launch. The [test ledger](https://github.com/cephalopod-ai/gosling/blob/main/docs/polish/test-ledger.md)
separates these results from older evidence.

The full 127-card campaign was not rerun after the repairs. Native startup failure dialogs,
crash/relaunch and external-backend fallback, folder-picker handoff, notification delivery, clean
shutdown, and the signed release/clean-machine matrix remain unverified in this local install.
Product decisions from the campaign, including `.goslingignore` enforcement, remain open.

## Updating

Follow [Updating gosling](/docs/guides/updating-gosling). A GUI reinstall replaces the app bundle,
including its embedded backend; it does not update a separately installed CLI. Check Desktop's
**Help > About** and the CLI's `gosling --version` independently. Keep configuration, sessions,
credentials, and the Research Library when replacing the app; no data reset is required for an
ordinary reinstall.
