# gosling v1.3.0

## Status

The repository declares version `1.3.0`. This page describes the source baseline and the changes
that followed its version bump; it does not assert that signed installers or a GitHub release were
published. Confirm an installed artifact with `gosling --version` and use the GitHub release page
for its publication and asset status.

## Highlights

- **Website logins.** Save a website, username, and password under **Settings → Credentials**. The
  model sees a named placeholder rather than the password; gosling checks the destination origin,
  substitutes the secret for the approved tool call, and redacts it from returned tool content.
  See [Website logins](/docs/guides/website-logins).
- **Folder-scoped approvals.** When a tool requests access to a specific working directory, the
  approval UI can allow that folder for the current session or add it to the global trusted-folder
  list. Existing read-only workspace policy still takes precedence.
- **Provider and model refresh.** Canonical model and provider metadata were refreshed, and Claude
  Code model-alias extraction now prefers the provider's resolved model identifier.
- **More reliable provider handoff.** Bootstrap handoff acknowledgement allows up to 120 seconds
  for CLI-backed providers to cold-start and run prompt hooks. Desktop model-switch failures now
  preserve the detailed ACP cause in the error message.

## Upgrade notes

- Existing sessions and website-login-free configurations need no migration.
- Website logins are opt-in and managed in Desktop. Auto mode permits substitution without a
  per-call prompt; other modes ask before use.
- A global folder approval is durable. Review **Settings → Chat → Trusted folders** when you no
  longer want future sessions to inherit that access.

For build, signing, packaging, and publication gates, follow the repository
[release checklist](https://github.com/cephalopod-ai/gosling/blob/main/RELEASE_CHECKLIST.md).
